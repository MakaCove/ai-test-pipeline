# 03 — 输出规范

> **Canonical Schema**：`_shared/项目分析结构.md`（本文件为执行侧补充说明）

## 输出文件

- **路径**：`test-artifacts/project-analysis-{yyyyMMdd-HHmmss}.json`
- **编码**：UTF-8
- **格式化**：2 空格缩进

## 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| `schema` | ✅ | 固定 `ai-test-pipeline/project-analysis/v1` |
| `project` | ✅ | 名称、类型、前后端栈与 baseUrl |
| `project.backend.entryFileCount` | 推荐 | Controller/Router 入口文件数 |
| `auth` | ✅ | 认证策略；`testAccount` 无则 `null` |
| `auth.publicEndpoints` | 推荐 | 匿名/白名单路径 |
| `scanLimitations` | ✅ | 本阶段未覆盖项，防下游误用 |
| `chainHints` | 推荐 | 可串联场景线索，供下游建立 flowChains |
| `downstream` | 推荐 | 下游须读的源码路径与产物名 |
| `modules` | ✅ | 按模块组织的端点 + 路由 |
| `modules[].endpoints[]` | — | method+path 唯一；`requestBody` 为初步字段名 |
| `modules[].endpoints[].sourceFile` | 推荐 | 便于下游定位 Controller |
| `modules[].routes[].component` | 推荐 | 页面组件相对路径 |
| `summary` | ✅ | 统计；**不是**用例条数目标 |

## 端点字段可信度

| 字段 | 说明 |
|------|------|
| `method`, `path` | 高 — 直接从路由注解提取 |
| `requiresAuth` | 中 — 须结合 Security/拦截器 |
| `requestBody`, `responseBody` | 低 — 仅参数/DTO 类型名；完整契约由 api-test-case-generate 补全 |
| `summary` | 中 — 来自方法名/注释/Operation 注解 |
| `chainHints` | 中 — 启发式线索，需下游用源码核实 |
