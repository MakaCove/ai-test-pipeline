# 02 — 完整执行工作流

```
任务进度：
- [ ] 步骤 1：定位项目结构与技术栈
- [ ] 步骤 2：分析后端 API 入口
- [ ] 步骤 3：分析前端路由
- [ ] 步骤 4：识别功能模块与优先级
- [ ] 步骤 5：汇总认证策略
- [ ] 步骤 6：填写 scanLimitations 与 downstream
- [ ] 步骤 7：生成并校验 JSON
- [ ] 步骤 8：写入磁盘并输出摘要
```

## 步骤 1：定位项目结构与技术栈

- 确认项目根目录；识别 monorepo / 前后端分仓。
- 确定后端、前端代码路径（**勿假设** `backend/`、`frontend/`）。
- 识别技术栈：读 `pom.xml` / `build.gradle` / `go.mod` / `package.json` / `pyproject.toml`。
- 记录 `baseUrl`：优先 `application.yml`、`vite.config`、`README` 中的端口。

## 步骤 2：分析后端 API

1. 按 `05_多栈扫描指南.md` 选择 Glob，查找 API 入口文件。
2. 逐个读取，提取：
   - 类/模块级 path 前缀
   - 每个端点的 HTTP method、完整 path
   - 方法参数名（Body / Query / Path / Header）
   - 返回值类型名（用于 `responseBody` 初步推断）
   - 是否标注 `@Valid`、是否需登录（结合 Security/拦截器）
3. 若有 OpenAPI，可交叉核对，**以代码为准**。
4. 汇总端点清单；统计 Controller/Router 文件数。

## 步骤 3：分析前端路由

1. 按 `05_多栈扫描指南.md` 查找路由配置。
2. 提取：`path`、`name`、`meta`（如 `requiresAuth`）、`component` 路径。
3. **打开主要页面组件**，写 1 句 `summary`（含主要交互类型）。
4. 记录全局布局路径（Layout、Sidebar）供功能测试参考。

## 步骤 4：识别功能模块

- 按 URL 前缀 / Controller 包名 / 路由 meta 自动分组；**模块名取自代码**。
- 为每模块分配 P0/P1/P2；核心 vs 辅助写入 `summary.coreModules` / `auxiliaryModules`。
- 将端点与路由归入对应 `modules[]`；纯前端页（无 API）可仅含 `routes`。

## 步骤 5：汇总认证策略

- 识别登录/注册/登出端点。
- 识别 token 传递方式（Header 名、格式）。
- 识别 `auth.type`（见 `05_多栈扫描指南.md`，**勿默认 JWT**）。
- 收集 `publicEndpoints`（白名单、匿名接口）。
- 测试账号：仅从文档/配置/种子数据读取；无则 `testAccount: null`。

## 步骤 6：填写 scanLimitations 与 downstream

- 列出本阶段未覆盖内容（DTO 校验、业务规则、控件级清单等）。
- 填写 `downstream` 块，指向下游须读的源码路径（见 `06_下游衔接.md`）。

## 步骤 7：生成并校验 JSON

- 按 `03_输出规范.md` 生成 JSON。
- 自检：
  - [ ] `schema` 正确
  - [ ] 端点 path 无重复（method+path 唯一）
  - [ ] `auth.type` 与代码一致
  - [ ] 无复制粘贴的示例模块名（与当前项目无关）
  - [ ] `summary` 数字与 `modules` 一致

## 步骤 8：写入磁盘并输出摘要

- 路径：`test-artifacts/project-analysis-{yyyyMMdd-HHmmss}.json`
- 更新 `test-artifacts/latest` 指向该文件。
- 按 `06_下游衔接.md` 模板输出摘要，**强调地图级局限**。
