# 项目分析 — 工作流

## 分析范围

- **只扫入口层**：Controller / Route / 前端 router，不深入 Service
- **如实记录**：认证、字段名从代码读取；禁止默认 JWT、admin/123admin
- **标注局限**：`requestBody` 仅为初步字段名；完整契约由下游读 DTO 补全
- **预标注主流程候选**：`mainFlowCandidates` + `stateHints` + `pageEntryHints`

**必分析**：API 端点清单、前端路由、认证机制、模块分组、`chainHints`、状态机线索、主流程候选
**不分析**：Service 内部、DB Schema、逐控件清单（留给用例生成）

输出结构见 [输出规范.md](输出规范.md)；下游见 [下游衔接.md](下游衔接.md)。

## 执行步骤

```
- [ ] 1. 定位项目结构与技术栈
- [ ] 2. 分析后端 API 入口
- [ ] 3. 分析前端路由
- [ ] 4. 识别模块与优先级
- [ ] 5. 汇总认证策略
- [ ] 6. 填写 chainHints
- [ ] 7. 填写 stateHints（扫描 DTO 状态枚举 + 状态推进端点）
- [ ] 8. 填写 mainFlowCandidates（汇总 chainHints + stateHints + crossModuleRefs）
- [ ] 9. 填写 pageEntryHints（扫描页面入口与操作按钮）
- [ ] 10. 填写 crossModuleRefs（扫描跨模块外键）
- [ ] 11. scanLimitations + downstream
- [ ] 12. 校验 JSON
- [ ] 13. 写入 test-artifacts/ 并输出摘要
```

### 步骤 1～3

- 技术栈与路径：读 `pom.xml` / `package.json` 等（**勿假设** backend/frontend 目录名）
- Glob 模式见 [多栈扫描指南.md](多栈扫描指南.md)
- 后端：method、path、参数概览、鉴权
- 前端：route、component、页面 summary（须打开组件）

### 步骤 7：stateHints

扫描 DTO/Entity 中的 `status`/`state`/`type` 枚举字段：
- 找出 Controller 中改变状态的端点（`/submit`、`/approve`、`/publish`）
- 记录状态流转路径：`DRAFT → SUBMITTED → APPROVED`
- 每个 transition 标注 `endpoint` 和 `evidence`

### 步骤 8：mainFlowCandidates

汇总前三步的线索，输出主流程候选：
- `chainHints.candidateChains` → `resource-lifecycle` 类型候选
- `stateHints[].transitions` → `state-transition` 类型候选
- `crossModuleRefs` → `cross-module` 类型候选
- 每条标注 `confidence`：`high`（双重验证）/ `medium`（仅源码）/ `low`（推测）

### 步骤 9：pageEntryHints

扫描前端页面：
- 每个模块的菜单入口、可点击按钮
- 判断操作类型：`create` / `state-transition` / `delete` / `export`
- 记录 `evidence`（组件文件名 + 按钮文案）

### 步骤 13

- `test-artifacts/project-analysis-{yyyyMMdd-HHmmss}.json`
- 更新 `test-artifacts/latest`
