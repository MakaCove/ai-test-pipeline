# 项目分析 — 工作流

## 分析范围

- **只扫入口层**：Controller / Route / 前端 router，不深入 Service
- **如实记录**：认证、字段名从代码读取；禁止默认 JWT、admin/123admin
- **标注局限**：`requestBody` 仅为初步字段名；完整契约由下游读 DTO 补全

**必分析**：API 端点清单、前端路由、认证机制、模块分组、`chainHints`  
**不分析**：Service 内部、DB Schema、逐控件清单（留给用例生成）

输出结构见 [输出规范.md](输出规范.md)；下游见 [下游衔接.md](下游衔接.md)。

---

## 执行步骤

```
- [ ] 1. 定位项目结构与技术栈
- [ ] 2. 分析后端 API 入口
- [ ] 3. 分析前端路由
- [ ] 4. 识别模块与优先级
- [ ] 5. 汇总认证策略
- [ ] 6. 填写 chainHints
- [ ] 7. scanLimitations + downstream
- [ ] 8. 校验 JSON
- [ ] 9. 写入 test-artifacts/ 并输出摘要
```

### 步骤 1～3

- 技术栈与路径：读 `pom.xml` / `package.json` 等（**勿假设** backend/frontend 目录名）
- Glob 模式见 [多栈扫描指南.md](多栈扫描指南.md)
- 后端：method、path、参数概览、鉴权
- 前端：route、component、页面 summary（须打开组件）

### 步骤 5～6

- 登录端点、token 传递方式、`publicEndpoints`
- `chainHints.candidateChains`：POST 创建 + GET/PUT/DELETE 等同资源链路

### 步骤 9

- `test-artifacts/project-analysis-{yyyyMMdd-HHmmss}.json`
- 更新 `test-artifacts/latest`
