# 01 — 分析范围

## 原则

- **只扫「入口层」**：Controller / Handler / Route 定义 / 前端 router，不深入 Service 实现。
- **如实记录**：认证类型、字段名、框架名从代码/配置读取；**禁止**默认填 JWT、admin/123admin。
- **标注局限**：本阶段 `requestBody`/`responseBody` 仅为 Controller 层可见的**初步字段名**；完整契约由下游读 DTO/VO 补全。

## 后端分析

### 必分析

| 内容 | 说明 |
|------|------|
| API 入口文件 | 见 `05_多栈扫描指南.md` 各栈 Glob 模式 |
| 端点清单 | method、完整 path、简要 summary、是否需鉴权 |
| 参数概览 | `@RequestBody`/`@RequestParam`/path param 名称（类型可选） |
| 基础路径 | API 前缀，如 `/api/v1` |
| 认证机制 | JWT / Session / Bearer UUID / API Key / Cookie 等，**按代码识别** |

### 可选但推荐

- 公开路径列表（`publicEndpoints`）
- Controller / Router 文件数量
- 全局异常处理类路径（供下游引用）
- OpenAPI/Swagger 文件路径（若存在，标注为补充来源）

### 不分析

- Service / Repository 内部逻辑
- 数据库 Schema、SQL
- 工具类、纯配置类（除非含 auth 白名单）
- DTO 级校验注解细节（留给 `api-test-case-generate`）

## 前端分析

### 必分析

| 内容 | 说明 |
|------|------|
| 路由配置 | path、name、component 路径、`meta`（如 `requiresAuth`） |
| 页面概览 | 每页 1 句 summary：主要交互类型（表单/表格/弹窗等），**须打开组件文件后写** |
| 全局布局 | 侧栏、顶栏、登录入口（影响功能测试前置） |

### 不分析

- 组件内部 state 细节
- CSS、主题
- 状态管理（Pinia/Redux）实现细节
- 逐控件清单（留给 `functional-test-case-generate` 建 featureInventory）
