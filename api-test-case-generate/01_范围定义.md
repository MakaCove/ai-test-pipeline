# 01 — 输入要求与分析范围

## 输入源（按优先级）

1. **project-analysis JSON** — `modules[].endpoints`、`auth`（推荐前置 project-analyzer）。
2. **Controller** — `@RestController`、`@GetMapping` 等。
3. **DTO / Request / Response** — record、class、校验注解。
4. **GlobalExceptionHandler** — HTTP status 与 body.code。
5. **API 文档 / OpenAPI** — 辅助，**不能替代**读代码。
6. **application.yml** — 端口、测试账号、API 前缀。

## 分析目标

产出 **端点契约清单（endpointContracts）** 及每个端点的 **scenarios[]**，而非「端点 × 固定 4 条」矩阵。

详见 [08_端点契约驱动设计.md](08_端点契约驱动设计.md)。

## 覆盖原则

| 维度 | 原则 |
|------|------|
| 端点 | analysis 中每个 endpoint 至少 1 条用例 |
| 契约场景 | 清单中每个 P0 scenario 有对应用例（`scenarioRef`） |
| 鉴权 | 需鉴权端点有 auth 场景 |
| 校验 | DTO 每个 `@NotBlank`/`@NotNull` 有典型失败场景 |
| 业务规则 | 唯一键、状态机、资源不存在等有对应用例 |

## 不覆盖

- 静态资源、Actuator（除非明确要求）。
- WebSocket/SSE（非 REST 核心时）。
- 未在代码中出现的假想字段或错误码。

## 与功能用例的边界

接口验证 **HTTP 契约**；功能验证 **UI**。共享 project-analysis，独立设计，**不比较条数**。
