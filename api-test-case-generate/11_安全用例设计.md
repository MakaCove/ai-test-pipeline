# 11 — 安全用例设计（越权与鉴权专项）

> 适用任意需要鉴权的 REST 项目。复用 `10_智能编排.md` 的**多会话 token 隔离**机制，
> 把 `scenarios[].type: "security"` 落实为可执行用例，而非仅枚举名。
> 原则：**安全断言是「期望被拒绝」，不是「期望成功」**。

与既有文档关系：

- `08_端点契约驱动设计.md`：识别端点与资源归属
- `10_智能编排.md` §7.1：注册/第二账号 token 隔离（本文件直接复用）
- 本文件：在契约场景里补充越权矩阵

---

## 1. 何时需要安全用例

满足任一即应补 `security` 场景：

| 信号 | 示例 |
|------|------|
| 端点操作**归属某用户/租户的资源** | `GET /api/v1/orders/{orderId}` |
| 路径/体含**他人可枚举的主键** | `{userId}`、`{orderId}` |
| 存在**角色差异**（普通用户 vs 管理员） | `/api/v1/admin/*` |
| 存在**鉴权豁免清单** | `auth.publicEndpoints` |

## 2. 越权矩阵（IDOR / BOLA）

核心思想：**用 A 的会话访问 B 的资源，应被拒绝（403/404）**。

### 2.1 前置 — 双账号会话

需要两套独立会话变量（**不得共用 `token`**，见 `10` §7.1）：

```json
{ "extract": { "token": "body.data.token" }, "produces": ["token"] }
{ "extract": { "tokenB": "body.data.token" }, "produces": ["tokenB"] }
```

- `token`：主账号 A（tier 0 登录 bootstrap）
- `tokenB`：第二账号 B（独立登录 happy 用例产出）

### 2.2 越权读取用例

A 创建资源得到 `orderId` → **B 用 `tokenB` 访问 A 的 `orderId`** → 期望被拒。

```json
{
  "id": "TC-API-ORDERS-SEC-001",
  "contractRef": "CTR-ORDERS-GET-002",
  "scenarioRef": "SCN-SEC-IDOR-READ",
  "module": "orders",
  "title": "安全 - 越权读取 - B 账号访问 A 的订单应被拒",
  "priority": "P0",
  "request": {
    "method": "GET",
    "path": "/api/v1/orders/{{orderId}}",
    "headers": { "Authorization": "Bearer {{tokenB}}" }
  },
  "dependsOnCases": ["TC-API-AUTH-B-001", "TC-API-ORDERS-001"],
  "consumes": ["tokenB", "orderId"],
  "assertions": [
    { "field": "status", "operator": "neq", "expected": 200 },
    { "field": "status", "operator": "regex", "expected": "^(403|404)$" }
  ],
  "executionTier": 7
}
```

> 关键：`orderId` 来自 A 的创建用例（`produces`），`tokenB` 来自 B 的登录。
> 断言期望 **403（明确拒绝）或 404（不暴露存在性）**，二者均算通过。

### 2.3 越权矩阵（按动作展开）

对每个归属型资源端点，展开为矩阵：

| 动作 | 主体 | 期望 |
|------|------|------|
| 读 GET/{id} | B 访问 A 的资源 | 403/404 |
| 改 PUT/{id} | B 修改 A 的资源 | 403/404 |
| 删 DELETE/{id} | B 删除 A 的资源 | 403/404 |
| 列表 GET（带租户） | B 列表不含 A 的数据 | 200 但不含 A 的 id |

列表越界用 `not_contains` 断言：

```json
{ "field": "body", "operator": "not_contains", "expected": "{{orderId}}" }
```

## 3. 鉴权专项（已在 10 覆盖，补强断言）

| 场景 | scenarioRef | 断言 |
|------|-------------|------|
| 无 token | `SCN-A-NOAUTH` | status 401 |
| 失效/篡改 token | `SCN-A-BADTOKEN` | status 401 |
| 越权角色（普通访问管理员） | `SCN-SEC-ROLE` | status 403 |
| 公共端点匿名可访问 | `SCN-A-PUBLIC` | status 200（白名单核对） |

篡改 token 用例（不依赖真实失效，构造非法值）：

```json
{
  "request": { "headers": { "Authorization": "Bearer invalid.tampered.token" } },
  "assertions": [ { "field": "status", "operator": "eq", "expected": 401 } ],
  "executionTier": 7
}
```

---

## 4. 编排注意

- 安全用例多为**消费型**，`executionTier` 取 7（auth-negative）或更后。
- 越权用例**禁止**写死他人主键（如 `id=2`）；必须 `consumes` 来自 A 的 `produces`，确保命中真实存在但不属于 B 的资源。
- B 账号若无独立测试账号，应在 `project-analysis.auth` 标注「缺第二账号，越权用例受限」，并在 `scanLimitations` 记录。

---

## 5. 验收要点

- [ ] 每个归属型资源端点至少 1 条越权读用例（`SCN-SEC-IDOR-*`）
- [ ] 越权用例断言期望 **403/404**，非 200
- [ ] 第二账号 token 使用独立变量名（`tokenB`），未覆盖 `token`
- [ ] 越权资源 id 来自真实创建用例的 `produces`，非硬编码
- [ ] 角色越权、篡改 token 场景已覆盖（若项目存在角色体系）

---

## 6. 反模式

| 反模式 | 正确做法 |
|--------|----------|
| 用 A 自己的 token 访问 A 的资源叫「安全测试」 | 必须跨账号（B 访问 A） |
| 越权断言写 `status eq 200` | 期望 `403/404` |
| 硬编码 `orderId=2` 充当他人资源 | `consumes` A 的 `produces` 真实 id |
| 第二账号复用 `produces: ["token"]` | 独立 `tokenB`（见 10 §7.1） |
| 不区分 401（未认证）与 403（已认证无权） | 鉴权缺失用 401，越权用 403 |
