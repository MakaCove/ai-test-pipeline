# 接口用例生成 — 工作流

## 输入与范围

| 来源 | 用途 |
|------|------|
| `project-analysis` | endpoints、auth、chainHints |
| 主流程 Controller/DTO | request 字段、鉴权 |
| GlobalExceptionHandler | status、body.code |
| application.yml | 测试账号、API 前缀 |

**产出**：`mainFlowInventory` + JSON 用例文件（见 [主流程识别与设计.md](主流程识别与设计.md)）。

**默认不做**：全端点穷举、每字段校验失败用例、分页筛选组合。

---

## 执行步骤

```
- [ ] 1. 读 project-analysis + chainHints
- [ ] 2. 识别 API 主流程 → mainFlowInventory
- [ ] 3. 配置 mockData（元信息 + 用例级）
- [ ] 4. 编写用例（登录 + TC-API-WF-*）
- [ ] 5. 智能编排（见 智能编排.md）
- [ ] 6. 验收（见 验收与输出.md）
- [ ] 7. 写入 test-artifacts/api-cases/ 并更新 latest
```

### 步骤 2：识别主流程

按 [主流程识别与设计.md](主流程识别与设计.md) 从 `chainHints` 与 Controller 归纳；只深读主流程涉及端点的 DTO。**数量不设上限**，凡真实主流程均列入清单。

### 步骤 3：mockData

```json
"mockData": { "customerId": "MOCK-CUST-001" }
```

外键用种子 id 或 mock 常量；创建唯一字段用 `AUTO-{{timestamp}}`；在 `mockHints` 标注来源。

### 步骤 4：编写用例

- 登录：`TC-API-AUTH-001`，`produces: ["token"]`，body 用 `{{username}}/{{password}}`
- 主流程：`TC-API-WF-*`，`flowRef` → `FLOW-*`，每用例一个 HTTP 请求，≥2 断言
- 链路：`dependsOnCases`、`extract`、`produces`、`consumes`

### 步骤 7：落盘

- `test-artifacts/api-cases/api-cases-{yyyyMMdd-HHmmss}.json`
- Schema 见 `_shared/接口用例结构.md`
