# 02 — 完整执行工作流

```
任务进度：
- [ ] 步骤 1：读取 project-analysis 与 auth
- [ ] 步骤 2：逐端点读 Controller/DTO，建立契约清单（08）
- [ ] 步骤 3：识别可串联场景并建立数据链路图（09）
- [ ] 步骤 4：为每个契约场景设计用例（07）
- [ ] 步骤 5：编排变量链、依赖关系与**智能编排**（10）
- [ ] 步骤 6：生成 JSON + coverage（含 endpointContracts）
- [ ] 步骤 7：契约覆盖验收（06 §9）
- [ ] 步骤 8：写入磁盘并更新 latest
```

## 步骤 1：读取输入

**优先**：`project-analysis-*.json` 的 `modules[].endpoints`、`auth`。

**回退**：扫描 `*Controller.java`、`docs/api-reference.md`、OpenAPI。

**不要**在此步骤计算「目标用例条数」或 `2.5×N`。

## 步骤 2：建立端点契约清单（核心）

对每个 endpoint：

1. 打开对应 Controller 方法。
2. 打开涉及的 DTO / Request record。
3. 按 [08_端点契约驱动设计.md](08_端点契约驱动设计.md) §2 填写 `endpointContracts[]` 与 `scenarios[]`。
4. 标注鉴权、分页、唯一键、状态机、业务 throw。

产出：`endpointContracts`（可先表格，最终写入 JSON meta）。

## 步骤 3：识别可串联场景并建立数据链路图

按 [09_接口数据链路驱动设计.md](09_接口数据链路驱动设计.md) 执行：

- 标记“生产者端点”（login/create/start）
- 标记“消费者端点”（query/update/delete/action）
- 形成链路：`生产者 -> 消费者`
- 预留 `dependsOnCases` / `produces` / `consumes`

## 步骤 4：编写用例

对 `scenarios[]` **每一项** 写 1 条用例（判定表多列各 1 条）：

- `contractRef` + `scenarioRef`
- `request` 字段名与 DTO 一致
- `assertions` 与 `GlobalExceptionHandler` 一致
- `designMethods` + `designRef`

遵循 [03_用例设计规则.md](03_用例设计规则.md)。

## 步骤 5：智能编排（通用 · 必做）

按 [10_智能编排.md](10_智能编排.md) **由 Agent 逐步执行**（不依赖特定项目脚本）：

1. 从 `endpointContracts` + `chainHints` 建立生产者→消费者图
2. 为 create/login happy 填写 `extract` + `produces`
3. 扫描 `{{var}}`，补全 `dependsOnCases` + `consumes`
4. 标注 `sessionImpact`；注册 token 与主 `token` 隔离
5. 赋值 `executionTier`（登录 0 → 创建 2 → 读 3 → 删 80 → 破坏性 90）
6. 拓扑排序，写入 `executionOrder`，**重排用例数组**
7. meta 写入 `coverage.orchestration`

跨模块 **workflow** 用例 tier=99，不替代单端点场景。

## 步骤 6：生成 JSON

- 结构见 [04_输出规范.md](04_输出规范.md)
- 推荐填写 `coverage.flowChains`（链路统计）
- ID：`TC-API-{模块}-{三位编号}`

## 步骤 7：验收

对照 [06_契约覆盖与验收标准.md](06_契约覆盖与验收标准.md) §9：

- 端点 100%
- P0 契约场景 100%
- 可串联场景具备“先产出、后消费”的链路表达
- **智能编排验收**（10 §11）：`executionOrder`、 `sessionImpact`、依赖 id 均有效
- 无 DTO/错误码幻觉

**未达标**：补充遗漏的**契约场景**，不是机械增加条数。

## 步骤 8：写入磁盘

- `test-artifacts/api-cases/api-cases-{yyyyMMdd-HHmmss}.json`
- 更新 `test-artifacts/latest`
