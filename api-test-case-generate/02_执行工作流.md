# 02 — 完整执行工作流

```
任务进度：
- [ ] 步骤 1：读取 project-analysis 与 auth
- [ ] 步骤 2：逐端点读 Controller/DTO，建立契约清单（08）
- [ ] 步骤 3：为每个契约场景设计用例（07）
- [ ] 步骤 4：编排变量链与执行顺序
- [ ] 步骤 5：生成 JSON + coverage（含 endpointContracts）
- [ ] 步骤 6：契约覆盖验收（06 §9）
- [ ] 步骤 7：写入磁盘并更新 latest
```

## 步骤 1：读取输入

**优先**：`project-analysis-*.json` 的 `modules[].endpoints`、`auth`。

**回退**：扫描 `*Controller.java`、`docs/api-reference.md`、OpenAPI。

**不要**在此步骤计算「目标用例条数」或 `2.5×N`。

## 步骤 2：建立端点契约清单（核心）

对每个 endpoint：

1. 打开对应 Controller 方法。
2. 打开涉及的 DTO / Request record。
3. 按 [08_端点契约驱动设计.md](08_端点契约驱动设计.md) §2 填写 `endpointContracts[]` 与 `scenarios[]`。
4. 标注鉴权、分页、唯一键、状态机、业务 throw。

产出：`endpointContracts`（可先表格，最终写入 JSON meta）。

## 步骤 3：编写用例

对 `scenarios[]` **每一项** 写 1 条用例（判定表多列各 1 条）：

- `contractRef` + `scenarioRef`
- `request` 字段名与 DTO 一致
- `assertions` 与 `GlobalExceptionHandler` 一致
- `designMethods` + `designRef`

遵循 [03_用例设计规则.md](03_用例设计规则.md)。

## 步骤 4：编排顺序

1. auth 登录（extract token）置顶
2. 创建类 POST（extract id）
3. GET 列表/详情
4. PUT/PATCH/动作
5. DELETE / destructive 置后

跨模块 **workflow** 用例单独标记，不替代单端点场景。

## 步骤 5：生成 JSON

- 结构见 [04_输出规范.md](04_输出规范.md)
- ID：`TC-API-{模块}-{三位编号}`

## 步骤 6：验收

对照 [06_契约覆盖与验收标准.md](06_契约覆盖与验收标准.md) §9：

- 端点 100%
- P0 契约场景 100%
- 无 DTO/错误码幻觉

**未达标**：补充遗漏的**契约场景**，不是机械增加条数。

## 步骤 7：写入磁盘

- `test-artifacts/api-cases/api-cases-{yyyyMMdd-HHmmss}.json`
- 更新 `test-artifacts/latest`

## 禁止的自动化方式

```text
for ep in endpoints:
    for i in range(PRIORITY_MIN_CASES[priority]):
        append(pool[i % len(pool)])  # 未读 DTO → 禁止
while len(cases) < 2.5 * N:
    append(generic_case)  # 凑数 → 禁止
```

脚本若采用上述逻辑，仅为 demo，不能替代本工作流。
