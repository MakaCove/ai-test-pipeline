# 03 — 结果判定与报告规则

## 结果状态

| 状态 | 图标 | 含义 |
|------|------|------|
| 通过 | ✅ | 所有断言通过 |
| 失败 | ❌ | 至少一个断言未通过 |
| 跳过 | ⏭️ | 前置条件未满足（登录失败、页面不可达、链路依赖缺失） |

## 断言判定方式

通过 `browser_snapshot` 返回的内容进行判定：

| 断言类型 | 判定方式 |
|----------|----------|
| `url_contains` | 快照元数据中的 URL 包含目标字符串 |
| `url_equals` | 快照元数据中的 URL 完全等于目标字符串 |
| `text_contains` | 快照的文本内容中包含目标文字 |
| `text_not_contains` | 快照的文本内容中不包含目标文字 |
| `element_visible` | 快照中存在目标描述的元素，且未被隐藏或禁用 |
| `element_hidden` | 快照中不存在目标描述的元素，或已被隐藏 |
| `count_gte` | 快照中匹配目标（按角色/名称）的元素数量 ≥ 预期值 |
| `count_eq` | 快照中匹配目标的元素数量 = 预期值 |

## 截图策略

- **断言失败时**：自动截图并保存，报告中的失败用例会附带截图路径。
- **步骤中有 `screenshot` 操作时**：按步骤执行截图。
- 截图保存路径：`test-artifacts/ui-reports/screenshots/{用例ID}_{步骤编号}_{时间戳}.png`

## 超时处理

- 单次浏览器操作超时时间：15 秒。
- 页面加载等待策略：
  - 导航后等待 2 秒再获取页面快照。
  - 如果快照显示页面仍在加载，再等待 3 秒后重试。
  - 最多等待 10 秒，超时则标记当前步骤失败。

## 重试策略

- **「元素引用过期」错误**：重新获取页面快照后重试当前步骤（最多重试 2 次）。
- **「点击被拦截」错误**：先使用 `browser_scroll` 将目标元素滚动到可见区域，再重试点击。
- **页面未响应**：等待 3 秒后重试。

## 链路判定规则（新增）

- 若 `dependsOnCases` 中任一上游用例失败，当前用例标记 `⏭️` 并记录「上游失败传递」。
- 若 `consumes` 或 `steps.useVar` 变量未在变量池中找到，当前用例标记 `⏭️` 并记录「链路变量缺失」。
- 若 `produces` 或 `steps.saveAs` 声明变量但执行后未产出，当前用例标记 `❌`。
- 链路用例纳入 `flowChains` 统计，不替代功能点覆盖统计。
