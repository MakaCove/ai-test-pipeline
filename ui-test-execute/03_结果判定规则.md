# 03 — 结果判定与报告规则

## 结果状态

| 状态 | 图标 | 含义 |
|------|------|------|
| 通过 | ✅ | 所有断言通过 |
| 失败 | ❌ | 至少一个断言未通过 |
| 跳过 | ⏭️ | 前置条件未满足（登录失败、页面不可达、链路依赖缺失） |

## 断言判定方式

默认通道 A（`scripts/run-functional-tests.mjs`）内置判定逻辑（与 `_shared/断言语法.md` 对齐）：

| 断言类型 | 判定方式 |
|----------|----------|
| `url_contains` | `page.url().includes(target)` |
| `url_equals` | `page.url()` 与目标 URL 等值（含尾斜杠兼容） |
| `text_contains` | `page.content()` 包含目标文字 |
| `text_not_contains` | `page.content()` 不包含目标文字 |
| `element_visible` | 选择器命中且 `locator.isVisible() === true` |
| `element_hidden` | 未命中或 `locator.isVisible() === false` |
| `count_gte` | 命中元素数量 `>= expected` |
| `count_eq` | 命中元素数量 `=== expected` |

> 单页探索走 MCP Browser 时，可按同一语义做等价判定；批量 JSON 执行以脚本结果为准。

## 截图策略

- **断言失败时**：自动截图并保存，报告中的失败用例会附带截图路径。
- **步骤中有 `screenshot` 操作时**：按步骤执行截图。
- 截图保存路径：`test-artifacts/ui-reports/screenshots/{用例ID}_{步骤编号}_{时间戳}.png`

## 超时处理

- 单次元素操作超时时间：10 秒（点击/输入等 locator 操作）。
- `wait` 步骤按 `value` 毫秒显式等待；空值默认 1000ms。
- 导航使用 `domcontentloaded` 等待策略；步骤异常按失败记录。

## 重试策略

- UI 执行器不做通用自动重试；失败即记录到当前步骤并继续判定。
- 若需重试，建议在用例中显式加入 `wait`、`scroll`、`click` 组合步骤，保持行为可复现。

## 链路判定规则（新增）

- 若 `dependsOnCases` 中任一上游用例失败，当前用例标记 `⏭️` 并记录「上游失败传递」。
- 若 `consumes` 或 `steps.useVar` 变量未在变量池中找到，当前用例标记 `⏭️` 并记录「链路变量缺失」。
- 若 `produces` 或 `steps.saveAs` 声明变量但执行后未产出，当前用例标记 `❌`。
- 链路用例纳入 `flowChains` 统计，不替代功能点覆盖统计。
