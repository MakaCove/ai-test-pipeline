# 02 — 完整执行工作流

```
任务进度：
- [ ] 步骤 1：定位用例文件
- [ ] 步骤 2：执行前机检（schema/追溯/链路）
- [ ] 步骤 3：确认前端可用性
- [ ] 步骤 4：解析用户指示 → 选定 browser profile 与用例范围
- [ ] 步骤 5：调用确定性执行器（按依赖顺序执行）
- [ ] 步骤 6：收集截图与结果
- [ ] 步骤 7：生成报告（执行器自动产出）
- [ ] 步骤 8：写入磁盘并输出摘要
```

## 步骤 1：定位用例文件

- 读取 `test-artifacts/latest` 或 Glob 最新 `functional-cases-*.json`。
- 验证首元素 `"schema": "ai-test-pipeline/functional-case/v1"`。
- 读取 `baseUrl`、`testAccount`（勿硬编码账号密码）。

## 步骤 2：执行前机检（强烈建议）

- 执行 `node scripts/validate-functional-cases.mjs --strict`。
- 发布前或主分支门禁建议：`node scripts/validate-functional-cases.mjs --strict --enforce-chain`。
- 机检失败时停止执行并先修复产物。

## 步骤 3：确认前端可用性

- Playwright：脚本启动前可 `fetch(baseUrl)` 或打开 `/login` 探测。
- MCP： `browser_navigate` → `browser_snapshot`。
- 不可达则提示启动前端（及后端）。

## 步骤 4：解析用户指示 → profile 与范围

**必读** `05_浏览器与Profile选择.md`。

1. 从用户话术映射 **profile**（默认 `playwright-headed`；本地 Chrome → `local-chrome-headed`；无头 → `playwright-headless` 或 `--headless`）。
2. 读取项目 `test-artifacts/ui-test.config.json`（若存在）；无则按 `_shared/ui-test-profile模板.md` 默认。
3. 若为有头 profile，默认注入最大化配置：`--start-maximized` + `viewport: null`（除非用户指定固定窗口尺寸）。
4. 确定范围：`--limit N` / `--all` / `--module` / `--ids`。
5. 组装 CLI（在包含 `test-artifacts/` 的目录执行，**不要** `cd test-artifacts`）：
   ```bash
   node scripts/run-functional-tests.mjs --limit 20
   node scripts/run-functional-tests.mjs --local-chrome --limit 20
   node scripts/run-functional-tests.mjs --headless --limit 20
   ```

## 步骤 5：调用执行器并执行用例

### 通道 A — Playwright 脚本（批量 JSON）

1. 在包含 `test-artifacts/` 的目录运行上述 CLI（与 `scripts/` 同级）。
2. 脚本负责：登录注入、`{{username}}`/`{{password}}` 替换、`dependsOnCases` 依赖排序、`saveAs/useVar` 变量传递、断言、截图。
3. 终端输出即「可见操作步骤」；`--slow-mo` 控制浏览器动作速度。

### 通道 B — MCP Browser（单页探索）

1. `browser_tabs` list → `browser_navigate` → `browser_lock`。
2. 按 `steps` 映射 MCP 工具；每步后 `browser_snapshot`。
3. 断言失败时 `browser_take_screenshot`。
4. 结束 `browser_lock` unlock。

## 步骤 6：收集截图与结果

- 截图：`test-artifacts/ui-reports/screenshots/{用例ID}_{tag}_{时间戳}.png`
- 汇总：总数、通过、失败、跳过、通过率、耗时、**profile/browser/headed**
- 汇总链路：链路用例数、链路通过率、链路中断原因（上游失败/变量缺失）

## 步骤 7：生成报告（执行器自动产出）

- 模板：`_shared/界面报告模板.md`
- 须记录：profile、browser、headed、slowMo
- 须增加：`flowChains` 统计与链路失败明细

## 步骤 8：写入磁盘并输出摘要

- 报告：`test-artifacts/ui-reports/ui-report-{yyyyMMdd-HHmmss}.md`
- 机读结果：`test-artifacts/ui-reports/ui-results-{ts}.json`（执行器固定产出）
- JUnit 报告：`test-artifacts/ui-reports/ui-junit-{ts}.xml`（供 CI 看板）
- 对话摘要含：profile、通过/失败、报告路径
- 回归对比（可选）：`node scripts/compare-results.mjs --kind ui`
