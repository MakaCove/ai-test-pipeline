# 07 — 功能测试用例设计方法

> 生成功能用例时，须按 **ISTQB**、**ISO/IEC/IEEE 29119** 与 **用户体验/可访问性测试** 业界实践，将设计方法落实到可执行 `steps` 与 `assertions`。  
> 每条用例标注主设计方法；`designRef` 引用规则编号或用户故事 acceptance criteria。

## 0. 标准依据

| 标准/指南 | 与本技能的关系 |
|-----------|----------------|
| **ISTQB CTFL** §4.2 | 等价类、边界值、判定表、状态迁移 |
| **ISTQB CTFL** §4.3 | **用例测试**（Use Case Testing）— 主成功路径与扩展流 |
| **ISTQB CTFL** §4.4 | 错误推测；探索性测试（轻量） |
| **ISO/IEC/IEEE 29119-4** | 组合测试（Pairwise）、测试用例属性 |
| **IEEE 829 / 29119-3** | 用例可追溯性（需求/故事 ID） |
| **启发式测试**（James Bach 等） | 检查清单、风险驱动补充 |

**说明**：**因果图**用于分析条件组合后**化简为判定表**执行，不单独作为执行 tag；**正交试验**落实为 **`组合测试`**（Pairwise）。

---

## 1. 方法分类体系（功能 / UI 专用）

### 1.1 基于规格的黑盒技术（ISTQB — 核心）

| tag | 英文 | 适用 |
|-----|------|------|
| `等价类` | Equivalence Partitioning | 表单输入有效/无效类 |
| `边界值` | Boundary Value Analysis | 长度、数量、分页、日期范围 |
| `判定表` | Decision Table Testing | 多条件决定 UI 结果（登录、提交、批量） |
| `状态迁移` | State Transition Testing | 任务/版本/评审状态与界面一致 |

### 1.2 组合测试（ISO 29119）

| tag | 英文 | 适用 |
|-----|------|------|
| `组合测试` | Pairwise Testing | 多下拉/多筛选组合（生成任务表单等） |

### 1.3 用户场景与流程（ISTQB Use Case Testing）

| tag | 英文 | 适用 |
|-----|------|------|
| `用例场景` | Use Case / Scenario Testing | 主成功路径 + 扩展/异常流；跨路由 ≥6 步 |

（兼容旧 tag `场景`，新生成优先 **`用例场景`**。）

### 1.4 经验与检查（Industry practice）

| tag | 英文 | 适用 |
|-----|------|------|
| `错误推测` | Error Guessing | 双击提交、未选行操作、会话过期 |
| `检查清单` | Checklist-Based Testing | 冒烟/回归：关键控件可见、导航可达 |
| `探索性` | Exploratory Testing（轻量） | 单条 charter：「在 X 页尝试 Y」并记录发现 |

**模块级要求**：设计方法 tag 应覆盖该模块**已识别功能点**的类型多样性；**等价类** + **用例场景**（若存在跨页主路径）优先选用。  
**不以**全文件某 tag 固定条数为验收条件（见 06、08）。

## 2. 各方法落地要点

### 2.1 等价类划分

| 控件 | 有效类 | 无效类 |
|------|--------|--------|
| 登录用户名 | `autotest` | 空、未注册、空格 |
| 项目编码 | `AUTO-001` | 空、非法字符、重复 |
| 筛选项 | 合法枚举 | 清空后默认行为 |

无效类断言：停留当前页、`element_visible` 错误提示、`url_contains` 不变。

### 2.2 边界值分析

用户名 3～32、密码 6～64：测 **2,3,32,33** 与 **5,6,64,65**；分页第 1 页/末页/每页条数边界。

边界值写在 `steps[].value`；断言前端校验或提交后 Message。

### 2.3 判定表测试

**登录 UI 判定表**（每列 ≥1 条）：

| 条件 | R1 | R2 | R3 | R4 |
|------|----|----|----|-----|
| 用户名有效 | Y | Y | N | N |
| 密码正确 | Y | N | Y | N |
| 进入工作台 | ✓ | ✗ | ✗ | ✗ |

**必做**：登录；新增项目（名称×编码）；生成任务（项目×版本×模型×模板）；批量（勾选×操作）。

### 2.4 状态迁移测试

| 对象 | UI 触发 | 断言 |
|------|---------|------|
| 版本 | 发布 | 状态文案/标签 |
| 生成任务 | 启动/取消 | 列表 status 列 |
| 用例评审 | 详情改状态 | 筛选后可见 |

每状态页 **≥3 条**：合法迁移、非法操作、展示一致。

### 2.5 组合测试（Pairwise）

生成任务、UI-NL 创建等多因子表单：**≥4 条** Pairwise 组合，非全排列。

`title` 列出因子水平摘要；`designRef`：`PAIRWISE-行2`。

### 2.6 用例场景测试（Use Case Testing）

ISTQB：**主成功路径** + **扩展流** + **异常流**。

| 编号 | 用例名 | 路径 |
|------|--------|------|
| UC-01 | 首次交付 | 登录→项目→version→asset→生成 |
| UC-02 | 评审闭环 | 列表→详情→改状态→筛选 |
| UC-03 | 接口用例库 | api-test-cases CRUD UI |
| UC-04 | UI-NL | cases→tasks→报告 |
| UC-05 | 导出 | 导出中心→下载 |
| UC-06 | 失败恢复 | 任务失败→重试/取消 |

全文件 **`用例场景`** 覆盖已识别的主成功路径与关键扩展流；步骤跨 ≥2 路由时标注 `featureRefs`。

### 2.7 错误推测

**按功能点需要选用**：推测易错交互（未选行操作、重复提交、会话失效等）。

### 2.8 检查清单测试

对 P0 路由维护 **冒烟检查清单**（每路由 ≥1 条）：

- 页面标题/面包屑可见
- 主操作按钮存在且可点
- 核心表格/表单区域可见

`tags`：`检查清单`；可与 `冒烟` 并存。

### 2.9 探索性测试（可选、轻量）

全文件 **0～3 条**：`designRef` 写 **Charter**（目标、时间盒、关注风险），步骤允许「尝试非法操作组合并记录实际结果」。

## 5. 验收清单（与 06、08 合并）

- [ ] 每个 P0 功能点在 `featureInventory` 中有对应用例（`featureRef`）
- [ ] 有输入域的功能点：等价类/边界值至少覆盖有效与典型无效
- [ ] 有登录/多条件提交：判定表规则有对应用例
- [ ] 有状态展示的功能点：状态迁移有 UI 断言
- [ ] 多因子筛选/表单：必要时使用组合测试，非机械全排列
- [ ] `coverage.byDesignMethod` 已填，且非 100% 单一 tag
- [ ] 无「仅为凑 tag 数量」而与功能无关的用例

---

## 6. 反模式

- 仅「打开页面」无设计方法 tag。
- 用例场景与业务无关的长点击序列。
- 判定表只写 R1 成功登录。
- 状态迁移不断言界面状态文案。
- 探索性用例无 charter、无明确观察点。
- 为达到 tag/条数 KPI 而添加与功能清单无关的用例。
