# 01 — 输入要求与分析范围

## 输入源（按优先级）

1. **project-analysis JSON** — `modules[].routes`、`auth`、`project.frontend`（推荐前置 project-analyzer）。
2. **路由配置** — `src/router/**`、`routes.tsx`、`App.tsx` 等。
3. **页面组件** — `views/`、`pages/` 下的表单、表格、弹窗。
4. **布局与导航（P0）** — 侧栏 `el-menu-item` / `NavLink` 文案、菜单分组、Tab 切换控件；用于建立 `routeMenuMap`（见 [10_用户操作路径驱动设计.md](10_用户操作路径驱动设计.md)）。
5. **权限守卫** — `beforeEach`、Route Guard（仅守卫专项用例允许 `navigate` 直链）。
6. **API 客户端** — `api/`、`services/`，辅助 `relatedApis` 与数据流描述。

## 分析目标

产出 **功能清单（featureInventory）**，而非「路由 × 固定条数」矩阵。

每个清单项应对应用户可感知的交互或业务规则；详见 [08_功能清单驱动设计.md](08_功能清单驱动设计.md)。

## 覆盖原则

| 维度 | 原则 |
|------|------|
| 路由 | 每条业务路由至少被用例触及，且来自真实功能 |
| 功能点 | P0 功能点 100% 有用例（`featureRef` 追溯） |
| 权限 | 若存在登录/重定向，覆盖未登录与已登录路径 |
| 导航路径 | 业务功能经菜单进入；`navigationModel: menu-driven`；禁止用 `navigate` 代替菜单 |
| 校验 | 页面源码中可见的前端校验应有对应用例 |
| 状态 | 若 UI 展示业务状态，覆盖主要状态迁移 |

## 不覆盖

- 与当前路由无关的第三方 iframe（除非需求明确）。
- 纯视觉/CSS（除非验收标准包含 a11y）。
- 未在代码或需求中出现的「假想功能」。

## 与接口测试的边界

功能用例验证 **UI 与交互**；接口契约由 api-test-case-generate 负责。两者共享 project-analysis，但**独立设计**，不比较条数。
