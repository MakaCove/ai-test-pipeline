# 09 — 数据链路驱动设计（通用场景）

> 目标：不仅覆盖“单点功能”，还要覆盖“功能之间的依赖链”。  
> 原则：**凡是业务上存在上游产出、下游消费的数据关系，都应建立链路用例或链路步骤。**

---

## 1. 适用范围（不是只针对登录/CRUD）

满足任一条件即视为“可串联场景”：

- 下游步骤依赖上游创建/选择/计算结果（ID、名称、状态、令牌、版本号、任务号等）
- 下游页面需要使用上游页面形成的上下文（当前租户、当前项目、当前环境、当前筛选）
- 操作存在明确生命周期（创建→提交→审批→发布→归档、入队→执行→完成等）
- 操作存在状态前置条件（只有某状态才能触发下一动作）

---

## 2. 识别方法（生成阶段必须执行）

对每个 `featureInventory` 项做依赖分析：

1. 该功能是否“生产数据”（create/select/compute）？
2. 该功能是否“消费数据”（query/edit/delete/approve/export）？
3. 若消费，输入来自哪里（上游功能点、外部固化数据、系统初始化数据）？

结论写入：

- 单点用例：`featureRef`
- 链路用例：`featureRefs` + `dependsOnCases`
- 用例级可选字段：`produces`、`consumes`
- 步骤级可选字段：`saveAs`、`useVar`

---

## 3. 通用编排模板（领域无关）

### 3.1 链路拆分

将业务链拆成“可复用节点”：

`准备上下文（ensure_session）` → `click_menu 进入模块` → `生产数据` → `click_menu 进入下游模块` → `消费数据` → `验证` → `清理`

### 3.2 顺序规则

- 生产者用例在前，消费者用例在后
- 同一链路下消费者必须显式引用生产者（`dependsOnCases`）
- 若同一用例内完成链路，至少通过 `saveAs/useVar` 体现数据传递

**链路识别完成后**，必须继续执行 **[11_智能编排.md](11_智能编排.md)**：补全依赖、分层、拓扑排序、写入 `executionOrder`。

### 3.3 命名建议

- 链路用例 id：`TC-FUNC-WF-{模块}-{编号}`
- `title` 建议体现生命周期词：`创建后修改并删除`、`提交后审批再发布`

---

## 4. 字段约定（向后兼容）

以下字段为**可选增强**，不破坏现有 v1 结构：

```json
{
  "id": "TC-FUNC-WF-ORDERS-001",
  "featureRefs": ["FEAT-ORDERS-001", "FEAT-ORDERS-002", "FEAT-ORDERS-003"],
  "dependsOnCases": ["TC-FUNC-ORDERS-001"],
  "produces": ["orderName", "orderId"],
  "consumes": ["orderId"],
  "steps": [
    { "step": 1, "action": "fill", "target": "名称输入框", "value": "AUTO-{{timestamp}}", "saveAs": "orderName" },
    { "step": 2, "action": "click", "target": "保存按钮", "value": "" },
    { "step": 3, "action": "fill", "target": "搜索框", "value": "{{orderName}}", "useVar": "orderName" }
  ]
}
```

---

## 5. 验收要点（链路维度）

- [ ] 所有可串联场景已识别，不仅限登录/CRUD
- [ ] 链路用例能体现“先产出再消费”
- [ ] `dependsOnCases` 引用的上游用例真实存在
- [ ] `consumes` 的变量至少在同链路的 `produces` 中出现
- [ ] 清理步骤存在（删除、回滚或唯一命名可重复执行）
- [ ] **智能编排已完成**（见 11）：`executionOrder` 连续、破坏性认证置后

推荐在发布前启用：

```bash
node scripts/validate-functional-cases.mjs --enforce-chain
```

---

## 6. 反模式

1. 有依赖关系却拆成互不关联的孤立用例
2. 链路用例只写页面跳转，不写数据传递
3. 消费步骤直接使用硬编码数据，绕过上游产出
4. `dependsOnCases` 指向不存在或顺序错误的用例
