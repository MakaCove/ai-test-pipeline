# 功能测试用例生成器

**核心原则：用例来自真实功能，而不是为了凑条数。**

输出符合 `_shared/功能用例结构.md` 的 JSON。交付标准是 **功能点覆盖完整、步骤可执行、可追溯**，不是「达到 N 条」。

## 前置（优先）

1. **优先**运行 **project-analyzer**（含 `modules[].routes`）。
2. 若 `project-analysis` 不可用，回退为：直接扫描路由与页面源码（`router`/`routes` + `views`/`pages`），并在产物中注明回退来源。
3. 阅读 **[08_功能清单驱动设计.md](08_功能清单驱动设计.md)**（方法论核心）。
4. 阅读 **[07_功能测试用例设计方法.md](07_功能测试用例设计方法.md)** 与 **[06_功能覆盖与验收标准.md](06_功能覆盖与验收标准.md)**。

## 做什么 / 不做什么

| ✅ 做 | ❌ 不做 |
|------|--------|
| 读每个路由对应页面源码，列出真实控件与业务动作 | 不读代码，按「每路由 4 条模板」循环 |
| 每个**已识别功能点**至少 1 条可验证用例 | 不为达标重复「打开页面」类用例 |
| 跨页面业务流程按用户故事编排 | 不强行对齐接口用例条数 |
| 控件 `target` 使用页面真实中文文案 | 不臆造「登录按钮」「确定」等 |
| 在元信息中输出 `featureInventory` 与覆盖映射 | 不以 `totalCases ≥ 3R` 作为验收主标准 |

## 执行顺序（摘要）

1. 读 `project-analysis` + 路由 → 页面组件映射。
2. **逐页建立功能清单**（见 08）：按钮、表单、弹窗、表格操作、校验、状态展示、权限。
3. 对每个功能点用 07 中的设计方法推导场景（有效/无效/边界/状态/流程）。
4. 编写 `steps` / `assertions`；标注 `featureRef` 指向清单项。
5. 验收：**功能覆盖率 100%（P0）**，路由覆盖率 100%，无空步骤/空断言。
6. 写入 `test-artifacts/functional-cases/functional-cases-{时间戳}.json`。
