# 智能编排（UI 主流程用例）

> 用于 `TC-FUNC-{MODULE}-{序号}` 主流程用例排序与链路补全。
> 编排只管顺序与依赖，不替代 `菜单导航与步骤.md` 的交互规则。

## 1. 编排输入

| 输入 | 用途 |
|------|------|
| `coverage.mainFlowInventory[]` | 主流程清单与 `trace.flowRefs` 追溯 |
| `coverage.routeMenuMap[]` | 菜单路径合法性检查 |
| `project-analysis.auth` | 登录前置与会话约定 |
| 已生成用例数组 | `steps`、`trace` |

## 2. 用例类型约束（硬规则）

- 允许：`TC-FUNC-AUTH-*` + `TC-FUNC-{MODULE}-{序号}`
- 禁止：按路由批量模板、分页/筛选专项、校验失败专项、纯打开页面专项
- 每条用例必须有 `trace.flowRefs`，且能映射到 `mainFlowInventory` 的 `FLOW-*`

## 3. 变量与依赖补全

### 3.1 变量分类

| 类型 | 示例 | 依赖策略 |
|------|------|----------|
| 系统变量 | `username` `password` `timestamp` | 不建立 dependsOn |
| 会话变量 | `sessionUser` | 来自登录用例 |
| 业务变量 | `orderTitle` `projectName` | 来自上游用例的 `saveAs/trace.produces` |

### 3.2 生产者识别

- 登录用例：`trace.produces: ["sessionUser"]`
- 主流程创建/选择步骤：`saveAs` 或 `trace.produces`

### 3.3 消费者补全

扫描步骤 `value/target/useVar` 中 `{{var}}`：

- 有生产者则补 `trace.dependsOn` + `trace.consumes`
- 除登录用例外，业务用例默认依赖登录用例，并以 `ensure_session` 开头

## 4. executionTier 规则

| tier | 含义 |
|------|------|
| 0 | `login-bootstrap` |
| 2 | `resource-create` |
| 3 | `resource-read` |
| 4 | `resource-update` |
| 5 | `resource-action` |
| 80 | `resource-delete` |
| 90 | `auth-destructive`（登出/改密） |

## 5. 拓扑排序

1. `trace.dependsOn` 建图
2. 先按 `executionTier`，再拓扑排序
3. 写 `executionOrder: 1..N`
4. 按 `executionOrder` 重排数组

## 6. 输出字段

- 用例级（trace 内）：`trace.dependsOn`、`trace.produces`、`trace.consumes`
- 用例级（根级）：`executionTier`、`executionOrder`
- 步骤级：`saveAs` / `useVar`
- 元信息建议：`orchestration` 或 `coverage.orchestration`

## 7. 验收清单

- [ ] 登录用例最前；业务用例不重复完整登录
- [ ] 业务变量消费有上游生产者
- [ ] 业务页入口走 `click_menu`（守卫专项除外）
- [ ] 无非主流程碎片用例（分页/校验失败/仅打开页面）

## 8. 反模式

- 每条用例都写完整登录流程
- 用 `navigate` 直链业务页替代菜单操作
- 使用 `{{projectName}}` 却无 `trace.dependsOn` / `trace.consumes`
