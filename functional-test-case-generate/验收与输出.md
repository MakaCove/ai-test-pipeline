# UI 用例 — 验收与输出

> 方法论：[主流程识别与设计.md](主流程识别与设计.md)

## 交付标准

| 优先级 | 标准 |
|--------|------|
| P0 | `mainFlowCoveragePercent` = 100% |
| P0 | 步骤 `target` 与页面源码一致 |
| P0 | 业务页经 `click_menu` 进入 |
| P1 | `executionOrder` 连续；链路变量可解析 |

## 输出路径

- `test-artifacts/functional-cases/functional-cases-{yyyyMMdd-HHmmss}.json`
- `navigationModel`: `"menu-driven"`
- Schema：`_shared/功能用例结构.md`

## coverage 必填

```json
{
  "mainFlowTotal": 5,
  "mainFlowsCovered": 5,
  "mainFlowCoveragePercent": 100,
  "uncoveredMainFlows": [],
  "orphanCases": 0,
  "routeMenuMap": [],
  "mainFlowInventory": []
}
```

## 验收清单

- [ ] 每条主流程的 `suggestedCaseIds` 均存在
- [ ] 步骤有源码依据；无违规 `navigate`
- [ ] 登录未重复编写；`trace.dependsOn` 可解析
- [ ] 用例 id 统一 `TC-FUNC-{MODULE}-{序号}`（登录为 `TC-FUNC-AUTH-*`）
- [ ] 无「打开页面/校验失败/分页」碎片凑数
- [ ] 菜单遍历法已完成

## 反模式

- 路由数 × 固定模板
- 分页/筛选/校验失败专项凑数
- 校验分支拆成多条主流程
- 未读页面就写「点击确定」
- 使用旧编码（`TC-FUNC-WF-*`、`FEAT-*`）
