# 02 — 完整执行工作流

```
任务进度：
- [ ] 步骤 1：读取 project-analysis 与路由清单
- [ ] 步骤 2：逐路由阅读页面源码，建立功能清单（08）
- [ ] 步骤 3：识别可串联场景并建立数据链路图（09）
- [ ] 步骤 4：为每个功能点推导测试场景（07）
- [ ] 步骤 5：编写用例 steps/assertions，绑定 featureRef/featureRefs
- [ ] 步骤 6：编排跨页业务流程与上下游依赖（若存在）
- [ ] 步骤 7：生成 JSON + coverage（含 featureInventory）
- [ ] 步骤 8：功能覆盖验收（06 §8）
- [ ] 步骤 9：写入磁盘并更新 latest
```

## 步骤 1：读取输入

**优先**：`project-analysis-*.json` 的 `modules`、`routes`、`auth`、`project.frontend`。

**回退**：直接扫描 `frontend/src/router/**` + 页面组件目录。

**不要**在此步骤计算「目标用例条数」。

## 步骤 2：建立功能清单（核心）

对每个 `routes[]`：

1. 定位 component 文件并**完整阅读**模板与脚本。
2. 按 [08_功能清单驱动设计.md](08_功能清单驱动设计.md) §2 填写清单项。
3. 标注 P0/P1、关联 API、校验规则、异步行为。

产出：`featureInventory[]`（可先 Markdown 表格，最终写入 JSON meta）。

## 步骤 3：识别可串联场景并建立数据链路图

按 [09_功能数据链路驱动设计.md](09_功能数据链路驱动设计.md) 执行：

- 标记“生产者功能点”（创建/选择/计算上下文）
- 标记“消费者功能点”（查询/编辑/删除/发布/导出）
- 形成链路：`生产者 -> 消费者`
- 记录链路节点对应的 `featureRef`，并预留 `dependsOnCases`/`produces`/`consumes`

## 步骤 4：推导测试场景

对清单中**每一项**问：

- 主成功路径是什么？（→ 用例场景 / 等价类有效类）
- 失败/校验分支有哪些？（→ 等价类无效类、边界值）
- 是否依赖状态或其它模块？（→ 状态迁移、preconditions）
- 用户可能怎么误操作？（→ 错误推测）

**没有识别到的功能点，不要写用例。**

## 步骤 5：编写用例

遵循 [03_用例设计规则.md](03_用例设计规则.md)：

- `target` = 页面真实文案
- `featureRef` / `featureRefs` = 清单项 id
- `designMethods` + `designRef` 说明设计依据

可串联场景中，建议补充：

- `dependsOnCases`（跨用例依赖）
- `produces` / `consumes`（用例级数据流）
- `steps[].saveAs` / `steps[].useVar`（步骤级数据流）

登录相关用例与上游生产者用例放前部；有数据副作用的加 teardown。

## 步骤 6：跨页业务流程与上下游依赖

仅当业务上存在真实端到端路径时编写（08 §5）：

- 步骤跨多个路由
- `featureRefs` 列出涉及功能点
- 使用 `dependsOnCases` 标注依赖关系（若拆为多条用例）
- 不虚构系统中不存在的页面或按钮

## 步骤 7：生成 JSON

- 结构见 [04_输出规范.md](04_输出规范.md) 与 `_shared/功能用例结构.md`
- 元信息 `coverage` 含 `featureInventory`、`featureCoveragePercent`
- 推荐填写 `coverage.flowChains`（链路统计）
- ID：`TC-FUNC-{模块}-{三位编号}`

## 步骤 8：验收

对照 [06_功能覆盖与验收标准.md](06_功能覆盖与验收标准.md) §8：

- P0 功能点 100% 覆盖
- 路由 100% 覆盖
- 可串联场景具备“先产出、后消费”的链路表达
- 无模板凑数、无控件名幻觉

**未达标**：补充遗漏的**功能点**与用例，而不是机械增加条数。

## 步骤 9：写入磁盘

- `test-artifacts/functional-cases/functional-cases-{yyyyMMdd-HHmmss}.json`
- 更新 `test-artifacts/latest`

## 禁止的自动化方式

以下方式与方法论冲突，**Agent 不得采用**：

```text
for route in routes:
    for template in [加载, 查询, 新增, 分页]:
        append(template)  # 未读页面 → 禁止
while len(cases) < targetMin:
    append(generic_case)  # 凑数 → 禁止
```

脚本若采用上述逻辑，只能作占位/demo，不能替代本工作流。
