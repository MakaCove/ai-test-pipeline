# 02 — 完整执行工作流

```
任务进度：
- [ ] 步骤 1：读取 project-analysis 与路由清单
- [ ] 步骤 2：扫描布局/侧栏，建立 routeMenuMap（10）
- [ ] 步骤 3：逐路由阅读页面源码，建立功能清单（08）
- [ ] 步骤 4：识别可串联场景并建立数据链路图（09）
- [ ] 步骤 5：为每个功能点推导测试场景（07）
- [ ] 步骤 6：按菜单路径编写 steps/assertions（10），绑定 featureRef/featureRefs
- [ ] 步骤 7：智能编排与上下游依赖（11）
- [ ] 步骤 8：生成 JSON + coverage（含 featureInventory、routeMenuMap、navigationModel）
- [ ] 步骤 9：功能覆盖与导航路径验收（06 §8、10 §6）
- [ ] 步骤 10：写入磁盘并更新 latest
```

## 步骤 1：读取输入

**优先**：`project-analysis-*.json` 的 `modules`、`routes`、`auth`、`project.frontend`。

**回退**：直接扫描 `frontend/src/router/**` + 页面组件目录。

**不要**在此步骤计算「目标用例条数」。

## 步骤 2：建立路由—菜单映射（核心）

按 [10_用户操作路径驱动设计.md](10_用户操作路径驱动设计.md) §3：

1. 打开布局组件（`App.vue`、`Layout.tsx` 等），提取侧栏/顶栏每个入口的**可见中文文案**与对应 `route`。
2. 记录菜单分组（若有 `menu-group-label` 等）。
3. 产出 `coverage.routeMenuMap[]`；`/login` 等无菜单页面标注 `navigation.type: direct`。

**禁止**用 `router.meta.title` 代替侧栏文案而不核对源码。

## 步骤 3：建立功能清单（核心）

对每个 `routes[]`：

1. 定位 component 文件并**完整阅读**模板与脚本。
2. 按 [08_功能清单驱动设计.md](08_功能清单驱动设计.md) §2 填写清单项。
3. 标注 P0/P1、关联 API、校验规则、异步行为。

产出：`featureInventory[]`（可先 Markdown 表格，最终写入 JSON meta）。

## 步骤 4：识别可串联场景并建立数据链路图

按 [09_功能数据链路驱动设计.md](09_功能数据链路驱动设计.md) 执行：

- 标记“生产者功能点”（创建/选择/计算上下文）
- 标记“消费者功能点”（查询/编辑/删除/发布/导出）
- 形成链路：`生产者 -> 消费者`
- 记录链路节点对应的 `featureRef`，并预留 `dependsOnCases`/`produces`/`consumes`

## 步骤 5：推导测试场景

对清单中**每一项**问：

- 主成功路径是什么？（→ 用例场景 / 等价类有效类）
- 失败/校验分支有哪些？（→ 等价类无效类、边界值）
- 是否依赖状态或其它模块？（→ 状态迁移、preconditions）
- 用户可能怎么误操作？（→ 错误推测）

**没有识别到的功能点，不要写用例。**

## 步骤 6：编写用例（菜单路径优先）

遵循 [03_用例设计规则.md](03_用例设计规则.md) 与 [10_用户操作路径驱动设计.md](10_用户操作路径驱动设计.md)：

- **认证**：`reset_session` → `open_login` → …；注册须 `switch_auth_tab`
- **业务模块**：`ensure_session` → `click_menu`（来自 routeMenuMap）→ 功能操作
- **禁止**：业务功能用 `navigate` 直达路由（守卫专项除外）
- `target` = 页面真实文案；`featureRef` / `featureRefs` = 清单项 id

可串联场景补充 `dependsOnCases`、`produces`/`consumes`、`saveAs`/`useVar`。

登录生产者用例放前部；有数据副作用的加 teardown。

## 步骤 7：智能编排（通用 · 必做）

按 [11_智能编排.md](11_智能编排.md) **由 Agent 逐步执行**：

1. 从 `featureInventory` 标出生产者/消费者（与 09 链路图合并）
2. 登录生产者 `produces` 会话变量；创建类对齐 `saveAs` / `produces`
3. 扫描步骤变量，补全 `dependsOnCases` + `consumes`
4. 登出/改密等标注 `sessionImpact: invalidate`，tier=90
5. 拓扑排序 → `executionOrder` → **重排用例数组**
6. meta 写入 `orchestration`

**不替代**菜单导航（10）：业务用例仍 `ensure_session` → `click_menu`。

## 步骤 8：生成 JSON

- 结构见 [04_输出规范.md](04_输出规范.md) 与 `_shared/功能用例结构.md`
- 元信息必填：`navigationModel: "menu-driven"`、`coverage.routeMenuMap`、`coverage.featureInventory`
- 推荐填写 `coverage.flowChains`（链路统计）
- ID：`TC-FUNC-{模块}-{三位编号}`

## 步骤 9：验收

对照 [06_功能覆盖与验收标准.md](06_功能覆盖与验收标准.md) §8 与 [10_用户操作路径驱动设计.md](10_用户操作路径驱动设计.md) §6：

- P0 功能点 100% 覆盖；路由 100% 覆盖
- 导航路径合规：业务用例无违规 `navigate`；`click_menu` 文案与 routeMenuMap 一致
- 可串联场景具备“先产出、后消费”的链路表达
- **智能编排验收**（11 §12）：登录置前、破坏性认证置后、`executionOrder` 连续
- 无模板凑数、无控件名幻觉

**未达标**：补充遗漏的**功能点**与用例，而不是机械增加条数。

## 步骤 10：写入磁盘

- `test-artifacts/functional-cases/functional-cases-{yyyyMMdd-HHmmss}.json`
- 更新 `test-artifacts/latest`

## 禁止的自动化方式

以下方式与方法论冲突，**Agent 不得采用**：

```text
for route in routes:
    for template in [navigate(route), 查询, 新增, 分页]:
        append(template)  # 未读页面 / 直链路由 → 禁止
while len(cases) < targetMin:
    append(generic_case)  # 凑数 → 禁止
```

脚本若采用上述逻辑，只能作占位/demo，不能替代本工作流。
