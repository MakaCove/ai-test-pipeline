# 02 — 完整执行工作流

```
任务进度：
- [ ] 步骤 1：定位用例文件
- [ ] 步骤 2：执行前机检（schema/追溯/链路）
- [ ] 步骤 3：确认后端可用性
- [ ] 步骤 4：初始化执行环境
- [ ] 步骤 5：按依赖顺序执行用例
- [ ] 步骤 6：收集结果与统计
- [ ] 步骤 7：生成 Markdown 报告
- [ ] 步骤 8：写入磁盘
```

## 步骤 1：定位用例文件

- 读取 `test-artifacts/latest` 获取最新时间戳。
- 定位文件：`test-artifacts/api-cases/api-cases-{时间戳}.json`。
- 如果 latest 不存在，使用 Glob 匹配 `api-cases-*.json`，按修改时间取最新。
- 解析 JSON 文件，验证第一个元素包含 `"schema": "ai-test-pipeline/api-case/v1"`。

## 步骤 2：执行前机检（强烈建议）

- 执行 `node scripts/validate-api-cases.mjs --strict`。
- 发布前或主分支门禁建议：`node scripts/validate-api-cases.mjs --strict --enforce-chain`。
- 机检失败时停止执行并先修复产物。

## 步骤 3：确认后端可用性

- 尝试发送 `GET {基础地址}/actuator/health` 或直接请求根路径。
- 如果不可达，提示用户启动后端服务后重试。

## 步骤 4：初始化执行环境

- 确定 `baseUrl`（默认 `http://localhost:8080`，可通过用例文件元数据或用户输入覆盖）。
- 初始化运行时变量表 `{}`（空对象），用于存储 extract 提取的值。
- 初始化结果列表 `[]`（空数组）。
- 记录开始时间。

## 步骤 5：按依赖顺序执行用例

对用例文件中的每个用例对象依次执行以下操作：

1. **依赖检查**：若存在 `dependsOnCases`，上游未完成则延后或跳过（记录原因）。
2. **变量消费检查**：若存在 `consumes`，运行时变量池缺失则跳过并记录「链路变量缺失」。
3. **变量替换**：扫描 `path`、`headers`、`body` 字段，将 `{{变量名}}` 替换为运行时变量表中的值。
4. **发送请求**：使用 Node.js 内置 `fetch` 编写临时脚本发送 HTTP 请求：
   - method：用例中定义的 HTTP 方法
   - url：`baseUrl + path`
   - headers：合并默认 Content-Type 后发送
   - body：JSON.stringify 后发送（formFields 时使用 FormData）
4. **验证断言**：对每个断言执行判定，记录通过/失败。
5. **提取变量**：如果有 `extract` 字段，从响应体中按路径取值，存入运行时变量表。
6. **链路产出校验**：若存在 `produces`，确认变量池中可解析这些变量，缺失则标记失败。
7. **记录结果**：每条用例记录 `{ id, 是否通过, 耗时, 断言结果列表, 错误信息 }`。

## 步骤 6：收集结果与统计

- 汇总数据：总数、通过数、失败数、跳过数、通过率、总耗时。
- 汇总链路数据：链路用例数、链路通过数、链路失败数、链路通过率。

## 步骤 7：生成 Markdown 报告

- 使用 `_shared/接口报告模板.md` 模板。
- 失败用例按优先级排序展示。
- 全部用例按执行顺序展示明细表。
- 增加链路段落：`flowChains` 统计 + 链路失败明细（依赖缺失、变量缺失、上游失败传递）。

## 步骤 8：写入磁盘

- 路径：`test-artifacts/api-reports/api-report-{yyyyMMdd-HHmmss}.md`
- 同时输出摘要到对话中。
