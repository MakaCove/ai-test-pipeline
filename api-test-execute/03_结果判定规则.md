# 03 — 结果判定与报告规则

## 结果状态

| 状态 | 图标 | 含义 |
|------|------|------|
| 通过 | ✅ | 所有断言通过 |
| 失败 | ❌ | 至少一个断言未通过，或请求发生异常 |
| 跳过 | ⏭️ | 前置条件未满足（依赖用例未完成、变量缺失、服务不可达） |

## 断言判定逻辑

编写 Node.js 临时脚本执行断言判定：

```javascript
function 判定(实际值, 操作符, 预期值) {
  switch (操作符) {
    case "eq":           return 实际值 === 预期值;
    case "neq":          return 实际值 !== 预期值;
    case "contains":     return String(实际值).includes(预期值);
    case "not_contains": return !String(实际值).includes(预期值);
    case "gt":           return Number(实际值) > 预期值;
    case "lt":           return Number(实际值) < 预期值;
    case "exists":       return 实际值 !== undefined && 实际值 !== null;
    case "not_exists":   return 实际值 === undefined || 实际值 === null;
    case "regex":        return new RegExp(预期值).test(String(实际值));
    case "type":         return typeof 实际值 === 预期值;
    default:             return false;
  }
}
```

从响应中按路径取值时，使用 `body.data.items[0].name` 点号 + 数组索引语法取值。

## 超时处理

- 单个请求超时时间设为 30 秒。
- 超时视为失败，错误信息字段记录「请求超时（30 秒）」。

## 重试策略

- 网络错误（ECONNREFUSED、ETIMEDOUT 等）自动重试 1 次。
- 非网络错误不重试，直接标记失败。

## 链路判定规则（新增）

- 若 `dependsOnCases` 中任一上游用例失败，当前用例标记 `⏭️` 并记录「上游失败传递」。
- 若 `consumes` 中变量未在变量池中找到，当前用例标记 `⏭️` 并记录「链路变量缺失」。
- 若 `produces` 存在但执行后未能从 `extract` 或变量池得到变量，当前用例标记 `❌`。
- workflow 用例默认纳入链路统计，不替代单端点契约覆盖统计。
