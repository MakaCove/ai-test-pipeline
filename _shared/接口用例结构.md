# 接口测试用例结构

接口测试用例文件是一个 **JSON 数组**：第一个元素为**元信息**（含 `coverage.endpointContracts`），其余为**用例对象**。

- 生成技能：`api-test-case-generate`（方法论见 `08_端点契约驱动设计.md`）
- 断言语法：`断言语法.md`
- 前置输入：`项目分析结构.md` 中的 `project-analysis-*.json`（地图级）

## 文件结构

```json
[
  {
    "schema": "ai-test-pipeline/api-case/v1",
    "generatedAt": "2026-05-28T14:23:00+08:00",
    "sourceAnalysis": "test-artifacts/project-analysis-20260528-154821.json",
    "totalCases": 42,
    "coverage": {
      "endpointTotal": 12,
      "endpointsCovered": 12,
      "endpointCoveragePercent": 100,
      "contractScenarioTotal": 38,
      "contractScenariosCovered": 38,
      "contractScenarioCoveragePercent": 100,
      "uncoveredScenarios": [],
      "orphanCases": 0,
      "byModule": { "orders": 15, "auth": 8 },
      "byPriority": { "P0": 30, "P1": 12 },
      "byDesignMethod": { "等价类": 12, "判定表": 4 },
      "designMethodsCovered": 5,
      "endpointContracts": [],
      "flowChains": {
        "chainScenarioTotal": 6,
        "chainScenarioCovered": 6,
        "chainScenarioCoveragePercent": 100
      }
    }
  },
  { "id": "TC-API-AUTH-001", "contractRef": "CTR-AUTH-POST-001", "scenarioRef": "SCN-HAPPY", "...": "..." }
]
```

## 元信息（首元素）

| 字段 | 必填 | 说明 |
|------|------|------|
| `schema` | ✅ | 固定 `ai-test-pipeline/api-case/v1` |
| `generatedAt` | ✅ | ISO 8601 时间 |
| `sourceAnalysis` | 推荐 | 引用的 project-analysis 文件路径 |
| `totalCases` | ✅ | 实际用例数（**结果值，非 KPI**） |
| `coverage` | ✅ | 覆盖统计与契约清单 |

### coverage 字段

| 字段 | 说明 |
|------|------|
| `endpointTotal` / `endpointsCovered` / `endpointCoveragePercent` | 端点是否均有契约条目 |
| `contractScenarioTotal` / `contractScenariosCovered` / `contractScenarioCoveragePercent` | **P0 契约场景**覆盖率，验收目标 **100%** |
| `uncoveredScenarios` | 未覆盖场景 id 列表，应为 `[]` |
| `orphanCases` | 无 `contractRef`+`scenarioRef`（且非 workflow）的用例数，应为 **0** |
| `endpointContracts` | 端点契约清单（生成依据，见下文） |
| `flowChains` | 可选：上下游链路覆盖统计 |
| `orchestration` | 推荐：智能编排元信息（见 api `10_智能编排.md` §9.2） |
| `byModule` / `byPriority` / `byDesignMethod` | 分布统计 |

**已废弃**：`targetMinCases`、`≥ 2.5N` 等条数 KPI 字段。

### flowChains（可选增强）

| 字段 | 说明 |
|------|------|
| `chainScenarioTotal` | 识别到的可串联场景总数 |
| `chainScenarioCovered` | 已通过用例表达链路的场景数 |
| `chainScenarioCoveragePercent` | `chainScenarioCovered / chainScenarioTotal * 100` |

当项目不存在可串联场景时，可不填该块。

## endpointContracts[]（契约清单）

写入元信息 `coverage.endpointContracts`。每条对应一个 API 端点（Controller 方法）。

```json
{
  "id": "CTR-ORDERS-POST-001",
  "endpointKey": "POST /api/v1/orders",
  "module": "orders",
  "method": "POST",
  "path": "/api/v1/orders",
  "requiresAuth": true,
  "request": {
    "contentType": "application/json",
    "bodyFields": [
      { "name": "customerId", "required": true, "validation": "@NotNull" }
    ],
    "queryParams": [],
    "pathParams": []
  },
  "response": {
    "successCode": 0,
    "successFields": ["id", "status"],
    "paged": false
  },
  "businessRules": ["customerId 须存在"],
  "scenarios": [
    { "id": "SCN-HAPPY", "type": "happy", "summary": "合法 body 创建成功" },
    { "id": "SCN-V-CID", "type": "validation", "summary": "customerId 缺失 → 400" },
    { "id": "SCN-A-NOAUTH", "type": "auth", "summary": "无 Bearer → 401" }
  ],
  "priority": "P0"
}
```

### scenarios[].type（按需选用）

`happy` | `validation` | `auth` | `business` | `boundary` | `state` | `http` | `security` | `workflow`

简单端点场景少、复杂端点多——**均合理**，不为凑数添加场景。

### ID 命名

| 类型 | 格式 | 示例 |
|------|------|------|
| 契约项 | `CTR-{MODULE}-{METHOD}-{序号}` | `CTR-ORDERS-POST-001` |
| 场景 | `SCN-{语义}` | `SCN-HAPPY`、`SCN-V-CODE` |
| 用例 | `TC-API-{MODULE}-{序号}` | `TC-API-ORDERS-003` |

## 用例对象

```json
{
  "id": "TC-API-AUTH-001",
  "contractRef": "CTR-AUTH-POST-001",
  "scenarioRef": "SCN-HAPPY",
  "module": "auth",
  "title": "认证 - 用户登录 - 合法凭证返回 token",
  "description": "POST /api/v1/auth/login，验证 200 且 body.code=0 且 token 存在。",
  "priority": "P0",
  "tags": ["冒烟测试", "认证"],
  "designMethods": ["等价类"],
  "designRef": "EP-凭证-有效类",
  "preconditions": ["测试账号已在系统中存在"],
  "request": {
    "method": "POST",
    "path": "/api/v1/auth/login",
    "headers": { "Content-Type": "application/json" },
    "body": { "username": "{{username}}", "password": "{{password}}" }
  },
  "assertions": [
    { "field": "status", "operator": "eq", "expected": 200 },
    { "field": "body.code", "operator": "eq", "expected": 0 },
    { "field": "body.data.token", "operator": "exists", "expected": null }
  ],
  "extract": {
    "token": "body.data.token"
  },
  "produces": ["token"],
  "executionTier": 0,
  "executionOrder": 1
}
```

### 流程用例（workflow）

跨端点编排时：

- `scenarioRef` 可为 `SCN-WF-*` 或清单中 `type: workflow` 的场景
- 可用 `contractRefs`（字符串数组）引用多个契约项
- 可用 `dependsOnCases`（字符串数组）引用上游用例
- `description` 须说明 extract 链与步骤顺序

```json
{
  "id": "TC-API-WF-001",
  "contractRefs": ["CTR-AUTH-POST-001", "CTR-ORDERS-POST-001"],
  "dependsOnCases": ["TC-API-AUTH-001", "TC-API-ORDERS-001"],
  "scenarioRef": "SCN-WF-CREATE-ORDER",
  "module": "orders",
  "title": "业务流程 - 登录后创建订单",
  "consumes": ["token", "orderId"]
}
```

## 用例字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | ✅ | `TC-API-{模块}-{编号}`，文件内唯一 |
| `contractRef` | 推荐 | 单端点用例：契约清单项 id |
| `contractRefs` | 条件 | 流程用例：多个契约 id |
| `dependsOnCases` | 否 | 当前用例依赖的上游用例 id 数组 |
| `scenarioRef` | 推荐 | 场景 id，与 `endpointContracts[].scenarios[].id` 对应 |
| `module` | ✅ | 小写英文模块名 |
| `title` | ✅ | 中文简短描述 |
| `description` | ✅ | 验证目标 |
| `priority` | ✅ | P0/P1/P2/P3 |
| `tags` | 否 | 业务标签 + 设计方法（见 generate/07） |
| `designMethods` | 否 | 设计方法名数组 |
| `designRef` | 否 | 等价类/判定表/Pairwise 等追溯 |
| `preconditions` | 否 | 前置条件 |
| `request` | ✅ | method、path、headers、body |
| `assertions` | ✅ | 见 `断言语法.md` |
| `extract` | 否 | `{ "变量名": "响应路径" }` |
| `produces` | 否 | 当前用例产出的变量名数组（供下游消费） |
| `consumes` | 否 | 当前用例消费的变量名数组（来自上游） |
| `executionTier` | 推荐 | 执行分层整数，越小越先（见 `10_智能编排.md` §6） |
| `executionOrder` | 推荐 | 落盘前排好序后的 1…N 序号 |
| `sessionImpact` | 否 | 可选 `invalidate`：执行后当前会话失效 |

### request 补充

| 字段 | 说明 |
|------|------|
| `body: "__FORM__"` | 文件上传；配合 `formFields` |
| `formFields` | multipart 表单字段 |

## 变量替换

在 `path`、`headers`、`body` 中使用 `{{变量名}}` 引用 `extract` 或环境变量：

```json
{
  "request": {
    "method": "GET",
    "path": "/api/v1/orders/{{orderId}}",
    "headers": { "Authorization": "Bearer {{token}}" }
  }
}
```

## 验收要点

- [ ] `coverage.endpointContracts` 来自 Controller/DTO 源码，非仅 project-analysis
- [ ] 每个 P0 `scenarios[]` 有对应用例（`scenarioRef` 100%）
- [ ] `orphanCases === 0`（workflow 除外须显式标注）
- [ ] 每条用例有 `executionOrder`（智能编排后）
- [ ] 不以 `totalCases` 与端点数比较论「达标/未达标」
