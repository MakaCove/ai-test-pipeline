# 功能测试用例结构

功能测试用例文件是一个 **JSON 数组**：第一个元素为**元信息**（含 `coverage.featureInventory`），其余为**用例对象**。

- 生成技能：`functional-test-case-generate`（方法论见 `08_功能清单驱动设计.md`）
- 断言语法：`断言语法.md`
- 前置输入：`项目分析结构.md` 中的 `project-analysis-*.json`（路由地图）

## 文件结构

```json
[
  {
    "schema": "ai-test-pipeline/functional-case/v1",
    "generatedAt": "2026-05-28T14:23:00+08:00",
    "baseUrl": "http://localhost:5173",
    "sourceAnalysis": "test-artifacts/project-analysis-20260528-154821.json",
    "totalCases": 35,
    "coverage": {
      "routeTotal": 8,
      "routesCovered": 8,
      "routeCoveragePercent": 100,
      "featureTotal": 32,
      "featuresCovered": 32,
      "featureCoveragePercent": 100,
      "uncoveredFeatures": [],
      "orphanCases": 0,
      "byModule": { "auth": 6, "orders": 12 },
      "byPriority": { "P0": 28, "P1": 7 },
      "byDesignMethod": { "等价类": 10, "用例场景": 3 },
      "designMethodsCovered": 5,
      "featureInventory": []
    }
  },
  { "id": "TC-FUNC-AUTH-001", "featureRef": "FEAT-AUTH-001", "...": "..." }
]
```

## 元信息（首元素）

| 字段 | 必填 | 说明 |
|------|------|------|
| `schema` | ✅ | 固定 `ai-test-pipeline/functional-case/v1` |
| `generatedAt` | ✅ | ISO 8601 时间 |
| `baseUrl` | ✅ | 前端访问地址 |
| `sourceAnalysis` | 推荐 | 引用的 project-analysis 文件路径 |
| `totalCases` | ✅ | 实际用例数（**结果值，非 KPI**） |
| `coverage` | ✅ | 覆盖统计与功能清单 |

### coverage 字段

| 字段 | 说明 |
|------|------|
| `routeTotal` / `routesCovered` / `routeCoveragePercent` | 路由是否均有功能点 |
| `featureTotal` / `featuresCovered` / `featureCoveragePercent` | **P0 功能点**覆盖率，验收目标 **100%** |
| `uncoveredFeatures` | 未覆盖功能 id，应为 `[]` |
| `orphanCases` | 无 `featureRef`/`featureRefs` 的用例数，应为 **0** |
| `featureInventory` | 功能清单（生成依据，见下文） |
| `byModule` / `byPriority` / `byDesignMethod` | 分布统计 |

**已废弃**：`targetMinCases`、`≥ 3R` 等条数 KPI 字段。

## featureInventory[]（功能清单）

写入元信息 `coverage.featureInventory`。每条对应一个**用户可感知**的交互功能点。

```json
{
  "id": "FEAT-ORDERS-003",
  "route": "/orders",
  "module": "orders",
  "type": "dialog",
  "name": "新建订单",
  "trigger": "点击「新建订单」",
  "elements": ["客户选择", "确认", "取消"],
  "validations": ["未选客户时确认按钮禁用或提示"],
  "sideEffects": ["列表刷新", "成功提示"],
  "relatedApis": ["POST /api/v1/orders"],
  "priority": "P0"
}
```

### type 枚举（按需选用）

`navigation` | `form` | `dialog` | `table-action` | `filter` | `batch` | `pagination` | `state-display` | `async` | `auth` | `readonly`

### ID 命名

| 类型 | 格式 | 示例 |
|------|------|------|
| 功能点 | `FEAT-{MODULE}-{序号}` | `FEAT-AUTH-001` |
| 用例 | `TC-FUNC-{MODULE}-{序号}` | `TC-FUNC-ORDERS-003` |

## 用例对象

```json
{
  "id": "TC-FUNC-AUTH-001",
  "featureRef": "FEAT-AUTH-001",
  "module": "auth",
  "title": "认证 - 用户名密码登录 - 合法凭证进入首页",
  "description": "在登录页输入有效凭证，提交后跳转至需登录的首页。",
  "priority": "P0",
  "tags": ["冒烟测试", "登录"],
  "designMethods": ["等价类"],
  "designRef": "EP-凭证-有效类",
  "relatedApis": ["POST /api/v1/auth/login"],
  "preconditions": ["后端服务可用", "测试账号存在"],
  "steps": [
    { "step": 1, "action": "navigate", "target": "/login", "value": "" },
    { "step": 2, "action": "fill", "target": "用户名输入框", "value": "{{username}}" },
    { "step": 3, "action": "fill", "target": "密码输入框", "value": "{{password}}" },
    { "step": 4, "action": "click", "target": "登录按钮", "value": "" },
    { "step": 5, "action": "wait", "target": "", "value": "2000" }
  ],
  "assertions": [
    { "type": "url_contains", "target": "/dashboard", "expected": true },
    { "type": "element_visible", "target": "用户菜单或头像", "expected": true }
  ],
  "teardown": [
    { "step": 1, "action": "click", "target": "退出登录", "value": "" }
  ]
}
```

### 流程用例（跨页）

涉及 ≥2 个功能点时：

```json
{
  "id": "TC-FUNC-WF-001",
  "featureRefs": ["FEAT-AUTH-001", "FEAT-ORDERS-003"],
  "module": "orders",
  "title": "用例场景 - 登录后新建订单",
  "tags": ["用例场景", "业务流程"]
}
```

## 用例字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | ✅ | `TC-FUNC-{模块}-{编号}`，文件内唯一 |
| `featureRef` | 推荐 | 单功能点 id |
| `featureRefs` | 条件 | 跨页流程：多个功能点 id |
| `module` | ✅ | 小写英文模块名 |
| `title` | ✅ | 中文简短描述 |
| `description` | ✅ | 用户视角验证目标 |
| `priority` | ✅ | P0/P1/P2/P3 |
| `tags` | 否 | 业务标签 + 设计方法 |
| `designMethods` | 否 | 设计方法名数组 |
| `designRef` | 否 | 追溯编号 |
| `relatedApis` | 否 | 关联 API，便于与接口用例对照 |
| `preconditions` | 否 | 前置条件 |
| `steps` | ✅ | 有序操作步骤 |
| `assertions` | ✅ | UI 断言（见 `断言语法.md`） |
| `teardown` | 否 | 清理步骤 |

### steps[].action

`navigate` | `click` | `fill` | `select` | `hover` | `wait` | `press_key` | `screenshot` | `scroll`

| 子字段 | 说明 |
|--------|------|
| `step` | 序号，从 1 开始 |
| `target` | 元素描述或 URL（navigate） |
| `value` | 输入值、等待毫秒、按键名 |

## 与接口用例的关系

| 维度 | 功能用例 | 接口用例 |
|------|----------|----------|
| 追溯键 | `featureRef` → `featureInventory` | `contractRef` + `scenarioRef` → `endpointContracts` |
| 验收 | P0 功能点 100% | P0 契约场景 100% |
| 数量 | 随 UI 复杂度自然得出 | 随 API 契约复杂度自然得出 |

二者**互补**，数量无需对齐。

## 验收要点

- [ ] `featureInventory` 来自 View/Page 源码，非模板四件套
- [ ] 每个 P0 功能点有对应用例（`featureRef` 或 `featureRefs` 含该 id）
- [ ] `orphanCases === 0`
- [ ] 不以 `totalCases` 与路由数比较论「达标/未达标」
