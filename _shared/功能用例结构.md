# 功能测试用例结构

功能测试用例文件是一个 **JSON 数组**：第一个元素为**元信息**（含 `coverage.mainFlowInventory`），其余为**用例对象**。

- 生成技能：`functional-test-case-generate`（方法论见 `主流程识别与设计.md`）
- 断言语法：`断言语法.md`
- 前置输入：`项目分析结构.md` 中的 `project-analysis-*.json`（路由地图）

## 文件结构

```json
[
  {
    "schema": "ai-test-pipeline/functional-case/v1",
    "generatedAt": "2026-05-28T14:23:00+08:00",
    "baseUrl": "http://localhost:5173",
    "navigationModel": "menu-driven",
    "sourceAnalysis": "test-artifacts/project-analysis-20260528-154821.json",
    "totalCases": 5,
    "coverage": {
      "mainFlowTotal": 4,
      "mainFlowsCovered": 4,
      "mainFlowCoveragePercent": 100,
      "uncoveredMainFlows": [],
      "orphanCases": 0,
      "routeMenuMap": [],
      "mainFlowInventory": [],
      "flowChains": {
        "chainScenarioTotal": 3,
        "chainScenarioCovered": 3,
        "chainScenarioCoveragePercent": 100
      }
    }
  },
  { "id": "TC-FUNC-WF-ORDERS-001", "featureRefs": ["FLOW-ORDERS-001"], "...": "..." }
]
```

## 元信息（首元素）

| 字段 | 必填 | 说明 |
|------|------|------|
| `schema` | ✅ | 固定 `ai-test-pipeline/functional-case/v1` |
| `generatedAt` | ✅ | ISO 8601 时间 |
| `baseUrl` | ✅ | 前端访问地址 |
| `navigationModel` | ✅ | 固定 `menu-driven`；步骤按菜单路径编排（见 `菜单导航与步骤.md`） |
| `sourceAnalysis` | 推荐 | 引用的 project-analysis 文件路径 |
| `totalCases` | ✅ | 实际用例数（**结果值，非 KPI**） |
| `coverage` | ✅ | 覆盖统计与主流程清单 |

### coverage 字段（主流程模式）

| 字段 | 说明 |
|------|------|
| `mainFlowTotal` / `mainFlowsCovered` / `mainFlowCoveragePercent` | **业务主流程**覆盖率，验收目标 **100%** |
| `uncoveredMainFlows` | 未覆盖主流程 id，应为 `[]` |
| `mainFlowInventory` | 主流程清单（生成依据，见下文） |
| `routeMenuMap` | 路由与侧栏菜单文案映射（menu-driven 必填） |
| `orphanCases` | 无 `featureRefs` 的用例数，应为 **0** |
| `flowChains` | 可选：上下游链路覆盖统计 |
| `byModule` / `byPriority` | 分布统计（可选） |

**可选（细粒度扩展或历史兼容）**：

| 字段 | 说明 |
|------|------|
| `routeTotal` / `routesCovered` / `routeCoveragePercent` | 主流程触及的路由统计 |
| `featureTotal` / `featuresCovered` / `featureCoveragePercent` | 功能点覆盖（非主流程模式验收项） |
| `featureInventory` | 可选 · 全站功能清单（非主流程模式验收项） |

元信息根级可另含 `orchestration`（见 `functional-test-case-generate/智能编排.md` §10.2）。

**已废弃**：`targetMinCases`、`≥ 3R` 等条数 KPI 字段。

### flowChains（可选增强）

| 字段 | 说明 |
|------|------|
| `chainScenarioTotal` | 识别到的可串联场景总数 |
| `chainScenarioCovered` | 已通过用例表达链路的场景数 |
| `chainScenarioCoveragePercent` | `chainScenarioCovered / chainScenarioTotal * 100` |

当项目不存在可串联场景时，可不填该块。

### routeMenuMap[]（menu-driven 必填）

从布局/侧栏组件提取，供 `click_menu` 步骤引用：

```json
{
  "route": "/projects",
  "menuLabel": "项目管理",
  "menuGroup": "资产管理",
  "requiresAuth": true
}
```

无侧栏页面（如 `/login`）：`menuLabel: null`，可附 `navigation: { "type": "direct" }`。

## mainFlowInventory[]（主流程清单）

写入元信息 `coverage.mainFlowInventory`。每条对应一项**核心业务主路径**。

```json
{
  "id": "FLOW-ORDERS-001",
  "name": "创建订单并在列表可见",
  "module": "orders",
  "priority": "P0",
  "userGoal": "业务用户新建订单并在列表中看到",
  "menuPath": ["订单管理"],
  "stepsSummary": "菜单进入 → 新建 → 填表提交 → 列表可见",
  "evidence": ["OrdersView.vue: 新建订单按钮"],
  "suggestedCaseId": "TC-FUNC-WF-ORDERS-001"
}
```

用例通过 `featureRefs: ["FLOW-ORDERS-001"]` 追溯。

## featureInventory[]（可选 · 功能清单）

写入元信息 `coverage.featureInventory`。每条对应一个**用户可感知**的交互功能点。

```json
{
  "id": "FEAT-ORDERS-003",
  "route": "/orders",
  "module": "orders",
  "menuLabel": "订单管理",
  "type": "dialog",
  "name": "新建订单",
  "trigger": "侧栏进入订单管理后点击「新建订单」",
  "elements": ["客户选择", "确认", "取消"],
  "validations": ["未选客户时确认按钮禁用或提示"],
  "sideEffects": ["列表刷新", "成功提示"],
  "relatedApis": ["POST /api/v1/orders"],
  "priority": "P0"
}
```

### type 枚举（按需选用）

`navigation` | `form` | `dialog` | `table-action` | `filter` | `batch` | `pagination` | `state-display` | `async` | `auth` | `readonly`

### ID 命名

| 类型 | 格式 | 示例 |
|------|------|------|
| 功能点 | `FEAT-{MODULE}-{序号}` | `FEAT-AUTH-001` |
| 用例 | `TC-FUNC-{MODULE}-{序号}` | `TC-FUNC-ORDERS-003` |

## 用例对象

```json
{
  "id": "TC-FUNC-AUTH-001",
  "featureRef": "FEAT-AUTH-001",
  "module": "auth",

  "description": "清理会话后打开登录页，输入有效凭证并提交。",
  "priority": "P0",
  "tags": ["冒烟测试", "登录"],
  "designMethods": ["等价类"],
  "designRef": "EP-凭证-有效类",

    { "step": 1, "action": "reset_session", "target": "", "value": "" },
    { "step": 2, "action": "open_login", "target": "", "value": "" },

    { "step": 4, "action": "fill", "target": "密码", "value": "{{password}}" },
```

### 流程用例（跨页）

涉及 ≥2 个功能点时：

```json
{
  "id": "TC-FUNC-WF-001",
  "featureRefs": ["FEAT-AUTH-001", "FEAT-ORDERS-003"],
  "dependsOnCases": ["TC-FUNC-AUTH-001"],
  "consumes": ["sessionUser", "orderId"],
  "module": "orders",
  "title": "用例场景 - 登录后新建订单",
  "tags": ["用例场景", "业务流程"]
}
```

## 用例字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | ✅ | `TC-FUNC-{模块}-{编号}`，文件内唯一 |
| `featureRef` | 推荐 | 单功能点 id |
| `featureRefs` | 条件 | 跨页流程：多个功能点 id |
| `dependsOnCases` | 否 | 当前用例依赖的上游用例 id 数组 |
| `module` | ✅ | 小写英文模块名 |
| `title` | ✅ | 中文简短描述 |
| `description` | ✅ | 用户视角验证目标 |
| `priority` | ✅ | P0/P1/P2/P3 |
| `tags` | 否 | 业务标签 + 设计方法 |
| `designMethods` | 否 | 设计方法名数组 |
| `designRef` | 否 | 追溯编号 |
| `relatedApis` | 否 | 关联 API，便于与接口用例对照 |
| `preconditions` | 否 | 前置条件 |
| `steps` | ✅ | 有序操作步骤 |
| `assertions` | ✅ | UI 断言（见 `断言语法.md`） |
| `teardown` | 否 | 清理步骤 |
| `produces` | 否 | 当前用例产出的变量名数组（供下游消费） |
| `consumes` | 否 | 当前用例消费的变量名数组（来自上游） |
| `executionTier` | 推荐 | 执行分层整数（见 `functional-test-case-generate/智能编排.md` §6） |
| `executionOrder` | 推荐 | 落盘前排好序后的 1…N 序号 |
| `sessionImpact` | 否 | 可选 `invalidate`：执行后需重新登录 |

### steps[].action

**会话与导航**（menu-driven）：

| action | target | 说明 |
|--------|--------|------|
| `reset_session` | — | 清除登录态 |
| `open_login` | — | 打开登录页 |
| `ensure_session` | — | 确保已登录（业务模块前置） |
| `click_menu` | 侧栏菜单可见文案 | 进入业务页面 |
| `switch_auth_tab` | `登录` / `注册` | 登录页模式切换 |
| `switch_tab` | 页内 Tab 文案 | 多 Tab 切换 |
| `navigate` | 路由 path | **仅**路由守卫/深链专项 |

**功能操作**：

`click` | `fill` | `select` | `hover` | `wait` | `press_key` | `screenshot` | `scroll`

| 子字段 | 说明 |
|--------|------|
| `step` | 序号，从 1 开始 |
| `target` | 元素描述；`click_menu` 为菜单文案；`navigate` 为 path（受限使用） |
| `value` | 输入值、等待毫秒、按键名 |
| `saveAs` | 可选：将本步骤产出保存为变量名 |
| `useVar` | 可选：声明本步骤消费的变量名 |

## 与接口用例的关系

| 维度 | 功能用例 | 接口用例 |
|------|----------|----------|
| 追溯键 | `featureRef` → `featureInventory` | `contractRef` + `scenarioRef` → `endpointContracts` |
| 验收 | P0 功能点 100% | P0 契约场景 100% |
| 数量 | 随 UI 复杂度自然得出 | 随 API 契约复杂度自然得出 |

二者**互补**，数量无需对齐。

## 验收要点

- [ ] `featureInventory` 来自 View/Page 源码，非模板四件套
- [ ] `navigationModel === "menu-driven"` 且 `routeMenuMap` 已填写
- [ ] 业务用例经 `click_menu` 进入页面（守卫专项除外）
- [ ] 每个 P0 功能点有对应用例（`featureRef` 或 `featureRefs` 含该 id）
- [ ] `orphanCases === 0`
- [ ] 每条用例有 `executionOrder`（智能编排后）
- [ ] 不以 `totalCases` 与路由数比较论「达标/未达标」
